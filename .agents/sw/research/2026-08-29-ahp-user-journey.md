# Research: AHP User Journey

## Question

How to use AHP as one user journey?

## Summary

AHP is used here as the connection between a local VS Code Agents window and
the VS Code Agent Host running inside an agent-capable Coder workspace. The
workspace is reached through the SSH configuration generated by Coder; the
Agent Host owns the session, so closing and reopening VS Code can reconnect to
the same active session.

## Detailed Findings

1. Start the platform and create an agent-capable workspace using the
   `docker-standard` template. The README's journey uses `make up`, an image
   build, a template push, and `coder create` with explicit parameters
   (`README.md:168-183`).
2. Run `scripts/configure-coder-ssh.sh`. It invokes `coder config-ssh --yes`
   and exposes the workspace as `ssh coder.<workspace-name>`
   (`scripts/configure-coder-ssh.sh:1-23`).
3. In VS Code, open the Agents window, select the Coder SSH host, and start an
   agent session. The documented route is Agents window -> AHP over SSH ->
   Coder host -> Agent Host -> repository/tools/terminal
   (`docs/phases/phase-1-remote-dev-agent.md:223-235`).
4. Give the agent a long-running task, close the project window, wait, reopen
   the Agents window, reconnect to the same host, and confirm the same session
   continued (`docs/phases/phase-1-remote-dev-agent.md:280-295`).
5. Session state is kept on the persistent `/home/coder` volume, including
   `.vscode` and `.vscode-server`; session synchronization is disabled by
   default so history stays on the private server
   (`docs/phases/phase-1-remote-dev-agent.md:239-268`).

## Important Boundary

The documented AHP durability applies to VS Code's built-in Agent Host
harnesses. `opencode` and `pi` run as terminal processes inside the workspace
and do not plug into AHP; their continuity is provided by a detached `tmux`
session instead (`docs/phases/phase-1-remote-dev-agent.md:368-385`).

## Protocol Check

For a non-GUI verification, run
`scripts/verify-ahp-session.sh coder.<workspace-name>`. The script tunnels the
remote Agent Host port over SSH and sends the AHP WebSocket JSON-RPC
`initialize` request; success requires `protocolVersion`, `serverSeq`, and
`defaultDirectory` in the response (`scripts/verify-ahp-session.sh:15-23`,
`scripts/verify-ahp-session.sh:81-136`).
