# Implementation Phases — Index

This directory splits `docs/INITIAL.md` into five sequential delivery phases, plus one optional, order-independent Phase 6. Each phase document is self-contained (objective, tasks, validation, manual E2E test, milestone reports) for the milestones it covers, opens with a mandatory **Required Reading** table of official best-practices/security docs for every tool it introduces, and ends with a mandatory documentation and `AGENTS.md` update step before its exit criteria are considered met. The full architectural rules, repository structure, and make-target contract that apply across all phases remain defined once in `docs/INITIAL.md` Sections 3–5 — do not duplicate them; refer back.

## Why this split

The original milestone order grouped the agent-facing developer experience behind infrastructure that isn't actually required for it (M2 runner, M8 Temporal). This phase split reorders delivery so that **Phase 1 alone already produces a usable, demoable outcome**: a remote development environment with an AI agent whose session survives disconnecting the editor. GitHub automation (Phase 2), durable orchestration and capability fabric (Phase 3), governance/observability (Phase 4), and full integration (Phase 5) are layered on afterward, each independently valuable and independently testable.

**Session Plane before Agent Harness:** within Phase 1 itself, M4 (VS Code Agent Host + AHP) and M5 (session persistence + worktrees) are deliberately placed before M9 (LLM/agent harness). The original plan treated VS Code purely as a remote editor and jumped straight to wiring in an LLM. That skipped the fact that VS Code's Agent Host is its own durable session plane, distinct from both the Coder workspace (M3) and any orchestration engine (M8, Temporal) — see `docs/INITIAL.md` Section 2.2 (Three Durability Levels) and Rule 7. Proving session infrastructure works before adding intelligence on top of it keeps these two concerns from being conflated when something breaks.

**Phase 1's M15 vs. Phase 6:** M15 originally conflated "reachable on the local network" with "reachable from anywhere" (Tailscale), blocking it on external infrastructure (a second network/device) that isn't always available. M15 now only covers local network/browser reachability — provable immediately, no external dependency. Wide-area access (Tailscale) moved to its own optional Phase 6, since nothing else in this plan depends on it (`docs/ARCHITECTURE.md` scopes Tailscale as "interactive remote access only, never for automation").

## Cross-cutting references (apply to every phase)

- **Section 2.2 — Three Durability Levels** (`docs/INITIAL.md`): UI durability (AHP), workspace durability (Coder), and process durability (Temporal) are distinct and each is tested independently — never assume one implies another.
- **Section 3 — Core Architectural Rules** (`docs/INITIAL.md`): Docker-first, one repo as source of truth, never commit secrets (incl. interim secret handling before OpenBao exists), GitHub as coordination plane, tool responsibility separation, no arbitrary external access, the three durability levels (Rule 7), and agent session data staying local by default (Rule 8).
- **Section 4 — Repository Structure** (`docs/INITIAL.md`): the full target repo layout, including `agent-host/`, `sessions/`, `cache/`, and `backup/`; each phase only creates the subset of paths relevant to its milestones.
- **Section 5 — Standard Make Targets** (`docs/INITIAL.md`): the stable `make` interface, including required script test coverage (`shellcheck` + `bats`).
- **Section 25 — Development Workflow**: one milestone per branch, PR, and merge only after acceptance criteria pass — this applies within every phase.
- **`/AGENTS.md`** (repo root): every phase must end with a "Documentation & Agent Instructions Update" step that updates this file's Guidelines, Agent Instructions, and appends a dated Lessons Learned entry — do not close out a phase without it. See each phase's own "Documentation & Agent Instructions Update" section for phase-specific detail.
- **Required Reading tables:** every phase begins with a table mapping each milestone to the official best-practices/hardening docs for the tool(s) it introduces (e.g. Coder, Temporal, GitHub Actions, gh-aw, MCP, OpenBao, OPA, Keycloak, OpenTelemetry, Prometheus, Grafana, Tailscale, VS Code Agent Host, `srt`). These are mandatory reading before starting that milestone, not optional background — the plan's own major-violation fixes (Temporal Task Queue naming, Grafana's mandatory Prometheus backend, gh-aw's real file-path convention, OpenBao unseal-key handling, etc.) were themselves found by checking the plan against these exact sources, so treat them as load-bearing, not decorative.
