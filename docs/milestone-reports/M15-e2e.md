## Open, unresolved limitations (documented, not silently worked around)

Same two `gh-aw` limitations recorded in `docs/security.md` under "M10",
re-confirmed live in this milestone:

1. **Docker-socket-proxy incompatibility.** `gh-aw`'s MCP Gateway/AWF
   sandbox needs a real Docker Unix socket; the M2 socket-proxy mitigation
   (`DOCKER_HOST=tcp://...`) is unsupported for this purpose. Not worked
   around here (would reopen the unauthenticated-root risk M2 avoided).
2. **No AI engine credentials** (`gh secret list` still returns empty).

Because of these, the gh-aw investigator's own reasoning content could not
be exercised end-to-end inside GitHub Actions in this environment — this
milestone instead used the M9-chosen harness (`opencode`) running locally
against the live stack for Step 7, exactly the pattern M11's manual
verification already established, and posted its real output to GitHub for
Step 8. Everything else — issue creation, deterministic CI build/fail/pass,
`workflow_run` trigger wiring, self-hosted-runner job pickup, the durable
Temporal workflow, and the governed Lab/Device API capability call — was
exercised for real, not simulated.
